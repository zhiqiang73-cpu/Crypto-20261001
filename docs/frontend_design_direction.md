# 量化交易系统前端 · 设计风格选型与落地规范

写于 2026-10-04。回答「什么样的设计适合量化交易系统前端、瑞士风格是否合适、还有哪些风格」。
结论先行：**瑞士风格适合做骨架，但不能照搬**；推荐「Swiss 网格 + 控制室告警纪律 + 机构交易台深色面板」三层混合。

---

## 1. 先看约束：量化前端不是「好看」，是六个硬约束

任何风格选择都必须先过这六关，过不了的风格再流行也不能用。

| # | 约束 | 对设计的直接要求 |
| --- | --- | --- |
| 1 | **信息密度** | 一屏要同时容纳行情、持仓、挂单、信号、日志、风控状态。留白是奢侈品 |
| 2 | **变化可感知** | 数字在跳，用户必须能瞬间看出「刚刚哪个值变了、往哪个方向变」 |
| 3 | **误读成本极高** | 单位、精度、正负号、标的归属错一位就是钱。对齐不是审美问题，是正确性问题 |
| 4 | **长时间注视** | 8 小时盯盘。暗底、低饱和、低眩光，避免大面积高亮色 |
| 5 | **告警显著性** | 正常态必须「安静」，异常态必须「喊出来」。视觉预算要留给告警 |
| 6 | **可核对** | 每个数字要能追溯来源（交易所订单号、信号 K 线时间）。界面上要有承载「出处」的位置 |

由此推出的总原则：**克制的装饰、极致的排版秩序、语义化的颜色、为告警预留的视觉预算。**

## 2. 风格地图

按「适配度」排序，适配度是对上面六个约束的综合判断。

### 2.1 瑞士国际主义风格（Swiss / International Typographic Style）——骨架最合适，但必须改造

- **特征**：严格网格、无衬线字体（Helvetica / Inter / 新怪诞体）、左对齐、零装饰、颜色只承载功能、字重和字号建立层级。
- **为什么适合**：量化系统的核心界面本质是**一堆需要对齐的数字**，而瑞士风格的网格系统天生就是为「对齐」服务的。它把装饰降到零，于是颜色可以专心地只表示语义——这正是交易界面最需要的。
- **局限（很关键）**：
  1. 教科书式 Swiss 是**白底**的，长时间盯盘会刺眼；必须换成深色。
  2. Swiss 的「大留白」和高密度**天然冲突**；必须把留白压缩成严格的行列节奏（间距全部走 4/8px 栅格，而不是「凭感觉留空」）。
- **结论**：**取其骨架（网格、字体纪律、色彩克制），弃其留白与白底。**

### 2.2 工业控制室 / SCADA HMI 风格（Control Room）——语义层最合适

- **特征**：深灰底、界面元素高度去饱和、**颜色只留给异常**（绿=正常、黄=注意、红=报警）、关键读数大字号、状态一眼可辨。源自电厂、航天、空中管制的成熟范式。
- **为什么对你特别合适**：你的系统里有**熔断（回撤 ≥10%）、日亏 ≥3% 停止开仓、灾难止损（3×ATR_1H）、人工干预检测**——这些本质都是「报警态」。控制室风格给了它们一套专门的视觉语言：颜色 + 位置 + 图标三重编码，而不是「把数字变红」这么单薄。
- **局限**：容易显得老气，需要用现代排版和现代色彩去救。

### 2.3 机构交易台 / 现代 Bloomberg 风格（Institutional Desk）——载体最合适

- **特征**：深色 + 面板化拼贴 + 高密度表格 + 迷你走势图（sparkline）+ 单一克制强调色 + 等宽数字。
- **代表产品**：Bloomberg 新版终端、TradingView 深色主题、Deribit、Hyperliquid、Koyfin、Alpaca；横向参考「可观测性美学」——Datadog、Grafana。
- **评价**：这是目前专业交易产品的**事实标准**，也是落地形态的首选。风险是容易做成「又一个深色后台」，需要靠排版纪律拉开差距。

### 2.4 终端 / 磷光风格（Terminal, Phosphor）——适合做「专家模式」，不适合做唯一风格

- **特征**：等宽字体、黑底、琥珀或绿磷光、功能键导航、全屏面板拼贴。
- **优点**：信息密度天花板最高，专业感强，纯键盘流。
- **缺点**：视觉疲劳、可访问性差、新人门槛高；更致命的是**「磷光色」占满了颜色预算，导致真正的告警色不再突出**。
- **用法**：作为一个可切换的「紧凑/专家视图」，而不是默认皮肤。

### 2.5 加密原生 / HUD 赛博朋克——不建议用于执行界面

- **特征**：霓虹发光、玻璃拟态、渐变边框、动效丰富。
- **评价**：品牌调性鲜明，适合面向散户的**营销页 / 资产页**；但在**下单与风控界面**上是负资产——对比度被压低、色彩噪声淹没告警、长时间注视疲劳、且容易让人误以为在玩游戏。**明确排除。**

### 2.6 极简日式 / 大量留白（Ma / Zen）——只能用在非核心页

优雅，但与密度约束正面冲突。只适合登录页、空状态、日报/复盘报告页。

### 2.7 新粗野主义（Neo-brutalism）

粗边框、硬阴影、高对比。在数据密度上其实不差，但气质随意，和「钱的严肃性」不搭，且不利于建立告警层级的细腻度。

### 2.8 消费级金融 App 风格（Robinhood / Apple HIG / Material）

大圆角、大留白、单一主数字、丰富动效。适合手机端**看结果**，不适合桌面端**做决策**。可作为移动端只读视图的参考，不能作为主界面语言。

### 2.9 适配度速查

| 风格 | 密度 | 告警显著性 | 长时间注视 | 专业可信感 | 综合建议 |
| --- | --- | --- | --- | --- | --- |
| 瑞士国际主义 | 高（改造后） | 高 | 高（改深色后） | 高 | **骨架** |
| 工业控制室 | 高 | 极高 | 高 | 高 | **语义层** |
| 机构交易台 | 极高 | 中高 | 高 | 极高 | **载体** |
| 终端/磷光 | 极高 | 低 | 中 | 高 | 专家模式可选 |
| 加密 HUD | 低 | 低 | 低 | 低 | 排除 |
| 极简日式 | 低 | 中 | 高 | 中 | 仅非核心页 |
| 新粗野主义 | 中高 | 中 | 中 | 低 | 排除 |
| 消费级金融 | 低 | 低 | 中 | 中 | 仅移动端只读 |

## 3. 推荐方案：三层混合「Swiss Terminal」

> **骨架 = 瑞士网格排版｜语义 = 控制室告警纪律｜载体 = 机构交易台深色面板**

一句话概括：**用瑞士风格的排版纪律，把高密度数据排得一丝不苟；用控制室的颜色纪律，让异常自动跳出来；用交易台的面板语言，把功能装进去。**

三者互补：Swiss 解决「对齐与克制」，控制室解决「告警不突出」，交易台解决「高密度深色如何不廉价」。

## 4. 落地规范

### 4.1 网格与间距

- **12 列主网格**，gutter 16px，页面左右 padding 24px（1440px 以下收窄到 16px）。
- **8px 基线网格**：所有间距只能是 4 / 8 / 12 / 16 / 24 / 32 / 48。禁止手调 7px、13px 这种「感觉值」。
- 面板必须**吸附到网格列**，宽度用列数定义，不用像素。
- 侧边栏固定 200–240px（不要 272px + 大 padding，小屏上是浪费）。

### 4.2 字体

- **界面字**：Inter 或 IBM Plex Sans；中文回落 `PingFang SC` / `Noto Sans SC` / `Source Han Sans`。macOS 上用 `-apple-system` 亦可。
- **数字**：全部使用**等宽或 tabular 数字**——`font-variant-numeric: tabular-nums` 或直接 IBM Plex Mono / JetBrains Mono / SF Mono。
  > 硬要求：比例数字在跳动时字宽会变，整张表会「呼吸抖动」，非常影响读数。
- **数字格式化**：固定小数位、千分位、单位独立成列（不要在数字里混单位）。
- **字号阶梯**（紧凑档 / 舒适档）：

| 用途 | 紧凑 | 舒适 |
| --- | --- | --- |
| 标签、辅助 | 11 | 12 |
| 表格正文、正文 | 12 | 13 |
| 面板标题 | 13 | 15 |
| 区块标题 | 15 | 20 |
| 关键读数 | 24 | 28 |
| 主价格 | 36 | 44 |

- 行高：表格 1.3（紧凑）/ 1.45（舒适）；正文 1.5。
- 字重只用 3 档（400 / 550 / 650），靠字号和颜色建立层级，不靠字重堆叠。

### 4.3 色彩系统

**三层背景 + 三级文本 + 四个语义色 + 一个强调色。**

```css
:root {
  /* 背景：近黑，不用纯黑 #000（眩光/光晕） */
  --bg-0: #0b0c0e;   /* 页面底 */
  --bg-1: #121417;   /* 面板 */
  --bg-2: #191c20;   /* 面板内嵌、表头 */
  --bg-3: #22262b;   /* 悬浮、选中 */

  /* 分割线 */
  --line: #23272c;
  --line-strong: #2e3339;

  /* 文本：三级，近白不用纯白 #fff */
  --text-0: #e8eaed;
  --text-1: #9ba1a8;
  --text-2: #666d75;

  /* 强调色：只用于「当前焦点」和「主操作」，不用于状态 */
  --accent: #4c8dff;
  --accent-soft: #16243d;

  /* 语义色（状态） */
  --ok: #30a46c;        /* 正常 */
  --warn: #d9a441;      /* 注意 */
  --danger: #e5484d;    /* 危险/报警 */
  --info: #4c8dff;      /* 信息 */

  /* 涨跌色（可切换约定，见下） */
  --up: #e87c7c;        /* 默认：中文习惯 红涨 */
  --down: #5bb98c;      /* 默认：中文习惯 绿跌 */
}
```

**三条关键纪律：**

1. **强调色 ≠ 状态色。** 强调色只标记「焦点/主操作」，语义色只标记「状态」。混用会让告警失去力度。
2. **涨跌色与告警色必须区分。** 中文习惯红涨绿跌，而红同时又是「危险」——两者会同色相打架。解决办法不是换色，而是**用不同的表现手段**：
   - 涨跌：**只用文字颜色**，中等饱和度（`--up` / `--down`）。
   - 告警：**满饱和色 + 背景块填充 + 图标 + 固定在固定位置**。

   这样即使同为红色，用户也不会混淆「这是亏钱」还是「这是系统报警」。
3. **涨跌约定必须可切换。** 中文用户默认红涨绿跌，欧美默认绿涨红跌。做成设置项，并且**永远同时给出箭头符号（▲▼）或正负号**，兼顾色盲用户。不要只靠颜色传达方向。

### 4.4 数字变化的表现

- **不要**缓动动画、不要「滚动数字」——缓动会让人误读瞬时值。
- 标准做法：**一次性高亮闪烁（flash-on-update）**，背景色 200ms 淡出，颜色按涨跌方向。这是交易终端的通用语言。
- 列表重排、面板展开：120–180ms 过渡。价格数字本身：0ms。
- 原则：**动效只用于解释状态变化，不做装饰。**

### 4.5 告警分级（控制室纪律的核心）

| 级别 | 场景（对应你的系统） | 视觉处理 |
| --- | --- | --- |
| L0 正常 | 运行器心跳正常、无挂单异常 | **不加任何颜色**。安静 |
| L1 信息 | 换仓、信号触发、错过 K 线补记 | 中性文字 + 淡色图标，进日志流 |
| L2 注意 | 日亏接近 3%、API 延迟升高、挂单长时间未成交 | 琥珀色文字 + 左侧色条，面板内提示 |
| L3 危险 | 熔断触发、灾难止损、人工干预检测、API 不可用 | 满饱和红 + 背景块 + 顶部横幅 + 需确认按钮 |

**风控状态条必须常驻可见**（不要藏在二级页面）。「Paper Mode / 测试网」「日亏额度」「回撤额度」「halted 状态」应该在每一页顶部都看得到。

### 4.6 表格

- 冻结表头；数值列**右对齐**，文本列左对齐，时间列等宽固定宽度。
- 斑马纹极弱或不用，改用 1px 分割线（`--line`）。
- 提供**密度开关**（紧凑/舒适），专业用户默认紧凑。
- 每行给出「出处」位：订单号、信号 K 线时间（北京时间）、策略 id 前缀（`kdj` / `kd5` / `e15` / `e5`）。

### 4.7 图表

- 主图：K 线 + 成交量 + KDJ/MACD 副图，十字光标跨图联动。
- **信号点直接标在图上**（B/S 标记），这是系统最核心的叙事——「为什么在这里开仓」。
- 图上标注 MACD 柱正负闸门与背离丢弃点，让「方向背离 → 丢弃」这个规则可见。
- 图表配色与界面同一套 token，不引入第二套色板。

### 4.8 降级态

API 不可用时必须**明确显示「无数据」**，绝不伪造数字（现有做法值得保持）。设计上给它一个**不丢脸的视觉处理**：空状态图标 + 「数据源未连接」文案 + 最后成功时间，而不是空白或 `--`。

### 4.9 交互

- 键盘优先：全局命令面板（⌘K）、数字键切换视图、`R` 刷新（已有）。
- 破坏性操作（解除熔断、恢复自动开仓）必须二次确认，且确认按钮不使用主强调色。

## 5. 反模式清单（明确别做）

- 玻璃拟态 / 毛玻璃背景 / backdrop-filter 大面积使用
- 大圆角（>8px）+ 大阴影的卡片堆叠
- 装饰性渐变按钮、装饰性插画、装饰性图标
- 价格数字使用缓动动画或滚动数字
- 用饱和色大面积填充背景
- 涨跌只用红绿、不给箭头或正负号
- 深色底上用纯黑 `#000` + 纯白 `#fff`（眩光 + 文字光晕）
- 强调色与状态色共用同一个色相
- 把风控状态藏在二级页面

## 6. 对现有 `frontend/` 的诊断

现状：`frontend/styles.css` 是**暖色暗调 + 13px 圆角 + 橙色强调（`#d97757`）**的 SaaS 风格。审美上不难看，但和量化场景有几处结构性冲突：

| 问题 | 现状 | 影响 | 建议 |
| --- | --- | --- | --- |
| **强调色与告警色打架** | `--accent: #d97757`（橙）与 `--amber: #d6a877`（警示琥珀）色相接近 | 品牌色和「注意」色几乎同色，异常状态不够跳 | 品牌橙**退到只出现在 logo 和主按钮**；语义色改用清晰的绿/琥珀/红三档，拉开色相与饱和度 |
| **圆角过大** | `--radius: 13px` | 偏消费级，牺牲密度和对齐严谨度 | 收到 4–6px；面板靠 1px 分割线而非阴影区分 |
| **阴影过重** | `--shadow` 带 12px/30px 投影 | 增加视觉噪声，占用告警预算 | 面板去掉投影，改用 `--line` 边框 |
| **缺等宽数字约定** | 字体栈有 `--mono` 但未强制用于数字 | 表格数字跳动时字宽抖动 | 对数值单元格加 `font-variant-numeric: tabular-nums` |
| **侧边栏过宽** | 272px + 26/18px padding | 1440p 以下浪费横向空间 | 收到 200–240px |
| **涨跌约定未声明** | `.positive { color: var(--green) }`（欧美习惯） | 中文用户可能读反 | 做成设置项，默认按用户习惯，并补箭头符号 |

**改造不是推倒重来**：`index.html` 的信息架构（交易总览 / 账户连接 / 图片显示确认模块 + 常驻侧边栏策略列表 + 风控状态）方向是对的，主要是把「视觉语言」从 SaaS 风格换成 Swiss Terminal。
