# BTC / ETH 15m KDJ×MACD 分层趋势跟随候选策略

> **状态：`worktree_candidate_not_deployed`。** 本文描述的是隔离工作树内的候选代码；未修改正在运行的系统，未重启运行器，未产生或修改任何委托。

## 1. 固定规格

| 项目 | 规格 |
|---|---|
| 标的 | BTCUSDT、ETHUSDT，各自独立记账与净仓同步，绝不混仓 |
| 周期 | 15 分钟；5 分钟仍仅保留作研究，不参与运行时账本 |
| KDJ | `(9, 3, 3)`；以收盘 K 线判定交叉 |
| MACD | `(12, 26, 9)`；仅使用能量柱正负过滤方向 |
| 执行时序 | 信号在已收盘的当根 15m K 线判定；现有净仓同步逻辑仍在下一根开盘后以限价追价执行 |
| 单层数量 | 沿用现有 `qty = equity × r / (k × ATR_1H)`，`r=0.03`、`k=2`，向下取整 |
| 分层上限 | **每标的、每条 15m 策略最多 3 层**；上限是硬限制 |

## 2. 完整决策矩阵

| 当前账本 | 已收盘 KDJ×MACD 信号 | 动作 | 账本结果 |
|---|---|---|---|
| 空仓 | 金叉 + MACD 正柱 | 开多第 1 层 | 多 1 层 |
| 已多 1–2 层 | 金叉 + MACD 正柱 | 同向加多 1 层 | 多层数 +1 |
| 已多 3 层 | 金叉 + MACD 正柱 | 忽略 | 保持多 3 层 |
| 空仓 | 死叉 + MACD 负柱 | 开空第 1 层 | 空 1 层 |
| 已空 1–2 层 | 死叉 + MACD 负柱 | 同向加空 1 层 | 空层数 +1 |
| 已空 3 层 | 死叉 + MACD 负柱 | 忽略 | 保持空 3 层 |
| 已多 | 死叉 + MACD 正柱 | 丢弃 | 不平仓、不反手 |
| 已空 | 金叉 + MACD 负柱 | 丢弃 | 不平仓、不反手 |
| 已多任意层数 | 死叉 + MACD 负柱 | 清掉全部多层后开空第 1 层 | 空 1 层 |
| 已空任意层数 | 金叉 + MACD 正柱 | 清掉全部空层后开多第 1 层 | 多 1 层 |
| 任意 | 熔断 / 日内风控闸门 | 禁止开新层与加层；有效反向可清仓但不反手 | 平仓或保持原仓 |

## 3. 实现约束

1. **背离优先于仓位管理**：MACD 方向不一致的交叉会在进入账本函数前被归为无信号，因此不会错误触发加仓、平仓或反手。
2. **旧状态兼容**：旧版单层 `entry` 被视为第 1 层；首次有效同向加仓时才升级为显式 `layers[]`，不需要迁移或改写旧状态。
3. **账户级聚合**：账本顶层继续输出总数量、数量加权均价和最新层的信号原因，因而原有净仓同步、面板和灾难止损仍能消费正确的账户级数值。
4. **有效反向统一离场**：虚拟账本会先删除全部旧层，仅保留新方向第 1 层；交易所执行仍使用原有的净额差值同步机制，不额外修改委托路径。
5. **可见性**：`position_sources` 与前端持仓行新增 `当前层数/最大层数`，例如 `BTC 15m · 2/3层`。

## 4. 风险警示与部署门槛

每层仍按当前单层 `r=0.03` 计算。因此若满 3 层，名义风险和敞口**可达到单层基准的约 3 倍**。这不是已获验证的收益改进，不应根据逻辑直觉直接部署。

候选版本至少应完成以下验证后，才进入单独的测试网激活评审：

1. 冻结 BTC / ETH 15m 历史数据，比较单层基线与 2 层、3 层上限版本；
2. 同时报告样本内、样本外、费用/滑点压力、资金费、最大回撤、满层暴露时间与反向净额翻转次数；
3. 使用同一手续费和下一根开盘成交口径，禁止收盘价同根成交和参数挑选后回填；
4. 样本外在 BTC 与 ETH 都不恶化，且成本压力后结论仍稳健；
5. 再由人工决定是否把候选分支合并到运行分支并重启运行器。
